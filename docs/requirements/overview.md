# 全体要件（システム共通）

このドキュメントは、本システムが**何を満たすべきか**（要件）だけをまとめたもの。

- どういう構造・仕組みで実現するか → [architecture.md](../architecture.md)
- コードをどう書くか → [coding-rules.md](../coding-rules.md)
- 機能別の要件 → [features/](./features/) 配下に機能単位で置く

> **運用ルール**: 案件からインプットされた要件は、会話やチャットの中に置いたままにせず、
> 必ずドキュメントに反映してからコードを書く。
> コードとドキュメントが食い違ったら、ドキュメント側を正として扱い、どちらかを直す。

## 1. システム概要

- 案件（プロジェクト）を管理する業務アプリケーションのサンプル実装。
- インターフェースは **Thymeleaf によるサーバサイドレンダリング画面のみ**（`/page/**`）。REST API は提供しない。

## 2. 利用環境・認証要件

- 利用者は**別システムの URL からこのアプリサーバへ**アクセスしてくる。
- 認証は **Azure Entra ID を IdP とする SAML 認証**で行う。
- 認証時、別システムから**ログイン ID** と**ユーザー種別**が連携される。アプリはこれをセッションで保持する。

## 3. 共通業務要件

### 業務時間チェック

- **リクエストのたび**に業務時間チェックを行う。
- 業務時間は**業務サービス状況テーブル**で管理されており、これを参照して判定する。
- 業務時間外の場合は**業務時間外エラー画面**に遷移する。

### セッションタイムアウト

- セッションタイムアウト時間を設定する（時間は未確定 → §7）。
- タイムアウトした状態でリクエストが来た場合は**セッションタイムアウト画面**に遷移する。

### 操作トラッキング

- ユーザーのセッションに ID を付与し、一連の操作をログでトラッキングできるようにする。
- ログから**ユーザー ID** と**クライアント IP** が分かること。
- 処理の流れを追えるよう、各レイヤーの開始・終了がログに残ること。

## 4. 画面共通要件

- ベースパス: `/page`。ルート `/` は案件一覧（`/page/projects`）にリダイレクトする。
- 登録・更新完了時はフラッシュメッセージで結果を通知する（PRG パターン）。リダイレクト先は画面遷移パターン（下記）に従う。
- バリデーションエラー時はフォーム画面を再描画し、フィールドの近くにエラーメッセージを表示する。

### 画面遷移パターン

画面の構成は以下の 3 パターンに分類する。

| パターン | 遷移フロー |
|---|---|
| A | 検索画面 →（検索実行）→ 一覧 → 更新画面 |
| B | 検索 or 登録画面 →（検索実行）→ 一覧 → 更新画面 |
| C | 検索 or 登録画面 →（登録実行）→ 自画面に遷移してメッセージ表示 |

**「戻る」の挙動**:

| パターン | 挙動 |
|---|---|
| A・B 共通 | 更新画面（戻る）→ **一覧**: ページングの選択状態を保持して表示 |
| A・B 共通 | 一覧（戻る）→ **検索（or 登録）画面**: 検索項目が入力された状態で表示 |
| B のみ | **更新完了後**に「戻る」を実行すると、一覧ではなく**検索 or 登録画面（入力画面）に戻る** |

**更新画面の初期表示**:

| パターン | 初期値のセット方法 |
|---|---|
| A | DB から取得した値をセット |
| B | **DB から取得せず、一覧画面から送られた値をそのまま入力値にセット** |
- エラー時の遷移先画面:

| 状況 | 画面 |
|---|---|
| システムエラー | 共通エラー画面 |
| 業務時間外 | 業務時間外エラー画面 |
| セッションタイムアウト | セッションタイムアウト画面 |
| 業務エラー | 元の画面を再描画してメッセージ表示 |

- 表示形式:

| データ種別 | 画面表示形式 |
|---|---|
| 日付 | `yyyy/MM/dd` |
| 数値（金額・数量等） | 3 桁カンマ区切り（例: `1,234,567`） |
| 区分値 | コードではなくラベル（表示名） |

## 5. データ要件

- DB は **Oracle**。接続には **Oracle Wallet** が必要。
- ユーザーが入力した日付は **`yyyyMMdd` 形式の文字列**で DB に格納する（例: `"20250104"`）。
- 登録日時・更新日時は **DB の `sysdate`** で記録する（アプリからは値を渡さない）。
- 区分値は**コード値**で DB に格納する。

## 6. セキュリティ・運用要件

- DB ユーザーのパスワード・Oracle Wallet 等の機密情報は **Azure Key Vault** で管理する。
  - Azure 環境からは**マネージド ID**、ローカル開発時は **Azure CLI 認証**（`az login`）でアクセスする。
  - ローカル開発でも Key Vault に接続する（ローカル専用のパスワード管理は行わない）。
- 設定ファイルにパスワード等の機密情報を直書きしない。
- ユーザーへ表示するメッセージはプロパティファイルで一元管理し、「処理完了・バリデーションエラー・業務例外・システム例外」の 4 種別で ID を分ける。
